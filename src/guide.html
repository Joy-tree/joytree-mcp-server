Before you start

  • A JoyTree account and API key. Find your key at joytree.site/dashboard/account, or run joytree apikey show. It starts with jtk_.
  • A Claude account with access to the Plugins page, where connectors are managed.
Using Cursor, ChatGPT or Lovable?

The same server address works in any MCP-compatible client. The screens below are Claude’s, but the steps are the same idea: add a remote MCP server, sign in with your key.

STEP 01

Open Plugins

In Claude, choose Plugins in the left sidebar. This is the home of every connector, from Google Drive to your own custom ones. Press Add in the top-right corner to start a new connector.

STEP 02

Add the connector

Fill in the custom connector form with the values below. Wording on Claude’s side can differ slightly between plans and releases, but the two things that matter never change.

FieldValue
NameJoyTree (any label you like)
Server URLhttps://mcp.joytree.site/mcp
Client ID / secretLeave blank. Claude registers itself automatically (OAuth 2.1).

Confirm, and Claude opens the Connect JoyTree page. Paste your API key and press Connect. You do this once.

Your key stays private

JoyTree verifies the key a single time, then swaps it for an opaque token. Claude never sees your raw key again.

STEP 03

Confirm it works

Back in Plugins, JoyTree now sits under Your plugins with an Active status. Open it to see its detail page.

“Can send data to mcp.joytree.site”

Claude shows this on every connector. It’s expected: it’s how your requests reach JoyTree.

STEP 04

Set permissions

This is the most valuable two minutes in the guide. Open the Permissions tab and choose, per tool or per group, when Claude is allowed to act. Tools are split into read-only tools (look, never touch) and tools that change things (deploy, delete, roll back, migrate).

The four modes

ModeWhat happensUse it for
Always allowfastClaude runs the tool without asking.Read-only lookups: listing projects, logs, metrics.
Needs approvalsafeClaude pauses and asks you each time.Anything that changes state: deploys, env vars, rollbacks, migrations, firewall.
BlockedoffClaude cannot use the tool at all.Tools you never want automated, such as joytree_delete_project.
CustomA mix, shown on a group header.Set automatically when you tune individual tools.
Recommended setup

Set Read-only tools to Always allow so Claude can investigate freely. Keep everything that changes something on Needs approval. Block joytree_delete_project if you never want Claude deleting projects.

Tools that change things

Scroll further and you’ll find the write tools, such as creating or deleting an alert rule, rolling back a deployment or starting a data migration. Expand Takes N inputs on any tool to see exactly what it will send, and Raw schema for the full definition.

Heads up

Firewall tools need a JoyTree Pro plan or above. On lower plans they return an error even when allowed.

FAQ

Troubleshooting

JoyTree’s tools aren’t showing up in my chat

Confirm the connector page says Connected, then open the … menu and choose Refresh tools list. Start a new chat afterwards so Claude loads the updated list.

The sign-in page rejects my key

Keys start with jtk_ and are checked against JoyTree when you press Connect. Copy a fresh one from your account page or run joytree apikey show. A key that has been regenerated or revoked will not work.

It worked yesterday, now Claude asks me to sign in again

Sign-in sessions are held in the server’s memory, so a restart or update on JoyTree’s side signs everyone out. Reconnect from Plugins and paste your key again. It takes about ten seconds and nothing is lost.

Claude asks for approval on every single lookup

Open Permissions and set Read-only tools to Always allow. Leave the state-changing tools on Needs approval.

Firewall tools return an error

The firewall is a Pro plan and above feature on JoyTree. Upgrade the plan, or leave those tools blocked.

How do I fully cut off access?

Use Disconnect (or Remove) in Claude. To also invalidate the credential itself, rotate your API key in the JoyTree dashboard.

TRUST

Security, in plain terms

  • Your key is exchanged, not shared. It’s verified once and replaced by an opaque OAuth token.
  • Everything runs as you. Each request is scoped to your own key. There’s no shared or server-wide credential anywhere.
  • No cross-talk. Every request gets its own isolated server instance, so one caller’s context can never leak into another’s.
  • You hold the brakes. Permissions in Step 4 decide what Claude can do without asking.
